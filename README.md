# Liga de Básquetbol — Ingeniería de Software II

Proyecto académico para la práctica final: **trabajo en equipo con GitFlow y nuevas funcionalidades**.

## Objetivo
Desarrollar progresivamente una aplicación web para gestionar una liga de básquetbol, usando historias de usuario, issues, ramas `feature/*`, pull requests y revisión de código.

## Flujo de ramas
- `main`: versión estable.
- `develop`: integración del trabajo del equipo.
- `feature/*`: desarrollo de cada nueva funcionalidad.
- `release/*`: preparación de versiones.
- `hotfix/*`: correcciones urgentes en producción.

## Dinámica de trabajo
1. Crear una historia de usuario en **Issues**, con criterios de aceptación.
2. Asignar responsable y mover su tarjeta a *In progress*.
3. Crear una rama `feature/` desde `develop`.
4. Programar y subir commits propios de la funcionalidad.
5. Abrir un pull request hacia `develop`.
6. Pedir una revisión real a otro integrante y corregir observaciones.
7. Integrar el PR cuando lo aprueben.
8. Preparar una rama `release/` y publicar la versión después de revisar los cambios.

> Las revisiones y colaboraciones deben ser realizadas por personas reales. No deben inventarse aprobaciones ni historial de commits.

## Puesta en marcha
La primera versión de la aplicación se desarrollará en la rama de funcionalidad y podrá abrirse en el navegador sin servidor.

## Entrega de la práctica
Revisar el enunciado: se entrega el **proyecto completo incluyendo la carpeta `.git`**, además de la evidencia de issues, PR, revisión y backlog. Para conservar `.git`, clonar el repositorio localmente y comprimir esa carpeta; **Download ZIP** de GitHub no incluye `.git`.
